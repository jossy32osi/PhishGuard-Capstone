# PhishGuard: Spot the Phish

## Practical Phishing Identification Exercise

### Purpose

This exercise helps participants practice identifying common warning signs in suspicious emails and messages.

All examples in this exercise are fictional and are provided for cybersecurity awareness and education.

---

# Instructions

Read each scenario carefully.

For each message:

1. Decide whether it is **Likely Legitimate** or **Suspicious**.
2. Identify the warning signs.
3. Explain what the recipient should do.

Remember:

> **STOP → CHECK → VERIFY → REPORT**

Do not click links or open attachments simply to investigate a suspicious message.

# Answer Key

## Scenario 1 — Suspicious

### Warning signs

* Strong urgency
* Threat of account suspension
* Unexpected security warning
* Request to use a verification link

### Recommended response

Do not click the link. Access the service through a trusted method or contact the organization using known legitimate contact information.

---

## Scenario 2 — Suspicious

### Warning signs

* Unexpected prize
* Request to provide information
* Encouragement to use a link
* No clear reason why the recipient was selected

### Recommended response

Do not use the link or provide personal information. Verify whether the promotion exists through an independently accessed official source.

---

## Scenario 3 — Suspicious

### Warning signs

* Urgent payment request
* Unusual request from a supposed manager
* Pressure to act quickly
* Lack of independent verification

### Recommended response

Do not make the payment based only on the message. Verify the request through a separate trusted communication channel and follow the organization's payment procedures.

---

## Scenario 4 — Suspicious

### Warning signs

* Unexpected delivery notification
* Request to use a link
* No independently verified delivery information
* Possible attempt to create concern about a missed delivery

### Recommended response

Do not click the link. If a delivery is expected, check its status using the official delivery service website or application accessed independently.

---

## Scenario 5 — Suspicious

### Warning signs

* Unexpected password-reset request
* Request for the current password
* Urgency
* Request for verification information

### Recommended response

Never provide a password through an unexpected message. Use the organization's normal account-management process or contact IT through a trusted channel.

---

## Scenario 6 — Suspicious

### Warning signs

* Request for a verification code
* Familiar-person impersonation may be possible
* Unusual login-related request
* Pressure to act quickly

### Recommended response

Never share a verification code with another person simply because they ask for it. Contact the colleague separately to verify the request and report the suspicious communication if appropriate.

# Key Lesson

A suspicious message does not need to look obviously fake.

Attackers may use familiar names, realistic language, urgent requests, or convincing stories.

The safest habit is to:

**STOP → CHECK → VERIFY → REPORT**

When in doubt, do not act on the message until the request has been independently verified.
